# 重要度の評価基準 — Version 1.7.0

Aは「自分の仕事や、普段使うAIの選択を変える価値が高い情報」。AI業界全体の重大ニュースという意味ではありません。

## 同じ比重で優先する3分野

| 分野 | 評価する用途の例 |
| --- | --- |
| 論文・情報の整理 | 論文PDFの比較、出典の照合、情報収集、NotebookLM・Zotero・Obsidianによる整理 |
| 資料・文章作成 | スライド、文書、原稿、報告書、図表、表計算、翻訳・校正 |
| 作業の自動化 | ファイル整理、定期的な情報収集、議事録、予定管理、AIへの作業依頼 |

3分野は同じ重みです。分野のキーワードを繰り返しても加点しません。複数分野へのつながりは小さな加点にとどめます。Settingsで選択を変更でき、画像・動画も任意で追加できます。すべて外すと、普段使うAIの重要な利用条件の変更を除いてAを付けません。

## 100点の内訳

| 項目 | 最大 | 判断すること |
| --- | ---: | --- |
| 仕事との関係 | 40 | 選んだ仕事の具体的な用途につながるか |
| 具体性 | 25 | 実際の操作・使い分け・変更内容・判断材料があるか |
| 効果 | 20 | 手間や成果、普段使うAIの契約・利用判断への影響があるか |
| 根拠 | 10 | 本文・確認済み字幕・十分な配信抜粋で内容を確認できるか |
| 新しさ | 5 | 公開から3日以内5点、7日以内4点、14日以内2点、30日以内1点 |

公式という理由で重要度を大きく加点しません。投稿の人気・再生数・強い宣伝表現は加点しません。新着枠はTodayの選出で別に扱い、新しさのためにAを付けません。

## A / B / C

| 評価 | 点数 | 意味と条件 |
| --- | --- | --- |
| A · 自分に重要 | 85以上 | 優先する仕事に直接つながり、具体性と効果を確認できる。通常は仕事との関係34以上・具体性20以上・効果16以上・根拠7以上が必要。普段使うChatGPT・Claude・Gemini等の料金・上限・データ設定の重要な情報は、仕事の語がなくても対象 |
| B · 試す価値あり | 60〜84 | 用途に合うか試す候補、比較のヒント、提供開始や詳しい手順を待つ情報 |
| C · 参考情報 | 59以下 | 仕事との関係が薄い、具体的な内容が不足、初歩的な講座、開発・API実装が中心の情報 |

まず実用的なA候補を集め、評価の後に、Todayの10件をA2件・B5件・C3件を目安に選出します。各記事の点数や重要度を比率に合わせて変更しません。A候補が不足する日は他の読める記事で補い、A1/B6/C3など実際の内訳を表示します。候補がすべてB/Cの日もあります。「理解した！」を押した記事は重要度に関わらずTodayから除外します。

## 点数より優先する制限

- API・SDK・開発キット・ハッカソン・環境構築・トークン単価などが中心ならC。簡単な設定・コピペ、論文や資料の具体的な作業をAIへ依頼する使い方は、内容を確認して対象にします。
- ニュースのまとめにAPI料金の値下げが含まれていても、個人向けチャットの月額・利用条件の変更とは区別します。料金という見出しだけでAの特例を適用しません。
- 超初心者向け、主な仕事と関係の薄い娯楽、iPhoneの自分の利用に直結しにくい限定機能はCまで。
- 一部の機能の提供時期が未確定、学生など特定の立場が前提、再現に必要な操作・構築手順が未公開ならBまで。
- YouTubeは情報源としてAの対象。ただし説明欄・章だけで動画の中身を推測してAにはしません。字幕内容を確認済みの実用情報で判定します。
- 「ハルシネーション完全ゼロ」などの強い効果の断言は根拠確認が必要なためBまで。一般的な新モデル発表で、優先する仕事が本文の一部に登場するだけならBまで。十分な内容がなく見出しだけならCまで。

制限により点数に上限を適用するため、内訳の合計と最終点が異なる場合があります。理由と条件は記事詳細の「この重要度の理由」で確認できます。

## 判定例（ニュースの実在を示す例ではありません）

- **A候補**：論文PDFを渡し、出典付きの比較表を作る具体的な手順。資料をスライドに変える実演。フォルダ整理をAIへ依頼する再現可能な方法。普段使うAIの個人プランの料金・上限・データ設定の変更。
- **B候補**：AIの活用に関する対談、新モデルの発表、公開日が決まっていない新機能、自作秘書の考え方だけ紹介する動画。
- **C候補**：SDKの更新、APIのトークン単価、開発環境の構築、超初心者向け基本操作、宣伝だけの投稿。

## A候補の収集と選出

- 3分野の具体的な手順・比較・成果物を優先して探します。note公式だけを読む収集から、[NotebookLM](https://note.com/hashtag/NotebookLM/rss)、[Obsidian](https://note.com/hashtag/Obsidian/rss)、[AI活用](https://note.com/hashtag/AI%E6%B4%BB%E7%94%A8/rss)の公開フィードを追加。[Zenn](https://zenn.dev/topics/notebooklm/feed)・[Qiita](https://qiita.com/tags/notebooklm/feed)のNotebookLMも確認します。タグに入っているだけで採用・A判定にはしません。
- 実務候補を最大100件のフィード枠へ優先して残し、本文を確認する最大40件の予算でも優先します。A候補の発見用の点数は、重要度を上げる点数ではありません。本文を確認して実装・宣伝が中心と分かれば対象から外します。
- 同じURLや転載を除外。同じnote著者の別タグ投稿を同じ発信元として扱い、Todayを1人の投稿だけで埋めません。公式・既存のYouTubeも収集を続けます。
- 各記事の85/60点の基準でA/B/Cを決めた後、A2・B5・C3を目安に選出。カテゴリー内では実用性・新着・発信元の多様性を考慮します。足りないカテゴリーは別の候補で補い、元の重要度を保持します。確認できない内容を補ってAにすることはありません。
- TodayはAから読む順に表示。同じ記事はExploreや詳細でも同じ判定です。「理解した！」で外れたら、未読のA候補がある場合だけAを補充します。
- 直近7日を中心に選び、十分な新着があっても30日以内の未読のA候補は比較します。古い公開日を新しい日付に変えません。10件未満は20/50/30％に近い整数を選出目安にします。

## 実装・保存・限界

`importance.js`を収集側と端末で共有します。取得・要約の後に評価し、字幕の補完後も再評価。端末では過去のキャッシュやブックマークの古い点数を引き継がず、現在の選択で判定します。記事ID・日時・本文・理解状況は変更しません。

公開データは汎用の3分野で評価します。Settingsの選択はlocalStorageに保存し、サーバーや公開JSONへ送りません。個人のチャット履歴・所属・研究計画は公開コードやフィードに含めません。

費用やAPIキーは不要です。これは有限のキーワード・確認状況による規則判定で、本文の意味、品質、実際の効果を完全には理解できません。字幕未取得の重要動画を過小評価する場合もあります。A/B/Cが合わない実例をもとに規則を調整します。将来、内容を読むAI評価を導入する場合は、同じ例で比較し、事実・利用条件の検証を別に行います。
